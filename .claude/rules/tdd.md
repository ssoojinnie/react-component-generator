# TDD Rule

> **이 규칙은 Rigid — 상황에 맞게 변형하지 마라.**
> 판단으로 우회할 여지가 없다. 아래 "적용 대상"에 해당하면 예외 없이 RED부터 시작한다.

## 1. 적용 기준

### TDD를 **반드시** 적용

- **비즈니스 로직** — 분기, 계산, 상태 전이, 정규화/변환
- **API** — 엔드포인트 핸들러, 요청/응답 스키마, 에러 응답
- **유틸 함수** — 순수 함수, 파서, 포매터, 검증기
- **버그 수정** — 버그를 재현하는 **실패 테스트를 먼저** 쓴다. 재현 없이 고치지 마라.

### TDD가 **불필요**

- **타입 정의** — `type` / `interface` 선언 (컴파일러가 검증)
- **설정 파일** — 빌드·린트·CI 설정, 환경 변수 로딩
- **순수 UI** — 로직 없는 마크업/스타일링
- **SQL** — 스키마 마이그레이션, 순수 쿼리문

경계가 애매하면 **적용하는 쪽**을 택한다. "UI처럼 보이는 로직"은 로직이다.

## 2. RED-GREEN-REFACTOR

### RED — 실패하는 테스트

- **하나의 동작 = 하나의 테스트.** 한 테스트에 두 동작을 담지 마라.
- **반드시 실행해서 실패를 확인한다.** 읽어보고 "실패할 것"이라 추정하는 것은 RED가 아니다.
- **실패 이유가 "기능 미구현"이어야 한다.** 오타, import 오류, 문법 에러로 인한 실패는 RED가 아니다 — 고치고 다시 실행하라.
- 기대값은 하드코딩한다. 구현을 호출해 기대값을 만들지 마라.

### GREEN — 통과하는 최소 코드

- **테스트를 통과시키는 최소한의 코드만 작성한다.**
- **YAGNI** — 지금 테스트가 요구하지 않는 분기, 옵션, 추상화, 범용화를 넣지 마라.
- **신규 테스트 + 기존 테스트 전부 통과를 확인한다.** 신규만 돌리고 넘어가지 마라.
- 설계가 아쉬워도 GREEN 단계에서는 손대지 않는다. REFACTOR에서 한다.

### REFACTOR — 구조 개선

- 허용: **중복 제거**, **이름 개선**, **헬퍼/모듈 추출**, 죽은 코드 삭제
- **green을 유지한다.** 각 리팩터 후 테스트를 다시 실행한다.
- **새 동작을 추가하지 마라.** 테스트 변경이 필요한 리팩터는 리팩터가 아니다.
- 개선할 게 없으면 건너뛴다. 억지로 추상화하지 마라.

### 반복

REFACTOR가 끝나면 **다음 동작에 대한 RED로 돌아간다.** 사이클은 작게, 자주 돌린다.

## 3. 삭제 강제 규칙

**테스트 전에 프로덕션 코드를 먼저 작성했다면, 그 코드를 삭제하고 RED부터 재시작한다.**

- "이미 썼으니 테스트를 뒤에 붙이자"는 TDD가 아니다. 삭제한다.
- **"참고용"으로 주석 처리하거나 다른 파일에 남기는 것도 금지한다.** 남겨두면 그 구현을 베끼게 되고, 테스트가 설계를 이끌지 못한다.
- 지워서 잃는 것은 몇 분이다. 테스트가 이끌지 않은 설계를 안고 가는 비용이 더 크다.

## 4. 변명 차단표

| 변명 | 반론 |
|---|---|
| "너무 단순해서 테스트 불필요" | 단순하면 테스트도 3줄이다. 비용이 없다. 단순하다는 판단 자체가 자주 틀리고, 단순한 코드가 깨졌을 때 아무도 의심하지 않아 가장 늦게 발견된다. |
| "나중에 추가하겠다" | 나중은 오지 않는다. 오더라도 그때 쓰는 것은 구현을 베낀 테스트이므로 버그를 함께 승인한다. 설계를 이끌 기회도 이미 지났다. |
| "시간이 없다" | TDD가 느린 게 아니라 디버깅이 느리다. 수동 확인 루프와 회귀 추적이 테스트 작성보다 오래 걸린다. 시간이 없을 때가 재작업을 감당할 여유가 가장 없을 때다. |
| "삭제하면 낭비" | 매몰비용이다. 이미 쓴 시간은 코드를 남겨도 돌아오지 않는다. 테스트 없이 작성된 코드는 검증되지 않은 가정의 집합이며, 그걸 유지하는 비용이 재작성 비용보다 크다. |
| "프로토타입이다" | 프로토타입은 살아남는다. 진짜 버릴 코드라면 애초에 커밋하지 마라. 커밋할 생각이라면 프로토타입이 아니라 제품 코드다. |

## 5. 프로젝트별 규칙 우선

**프로젝트의 `CLAUDE.md` / `AGENTS.md`에 TDD·테스트 규칙이 있으면 그것을 우선한다.**

- 이 파일은 **기본값(fallback)** 이다. 프로젝트가 침묵할 때만 적용된다.
- 충돌하면 프로젝트 문서가 이긴다. 테스트 러너, 파일 위치, 커버리지 기준 같은 구체 사항은 프로젝트 문서에서 가져온다.
- 프로젝트 문서가 더 느슨하더라도 그쪽을 따른다. 다만 어느 규칙을 적용했는지 사용자에게 밝혀라.
